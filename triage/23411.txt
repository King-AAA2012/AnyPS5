VERDICT: ACCEPT
SUMMARY: The AnyPS5 double/float libm (exp, exp2, cosh, sinh, pow, ldexp, etc.) does not match the flags/errno of the libc.prx bundled with PPSA10122 (SDK 5.00), most notably returning DBL_MAX/subnormals instead of ±Inf with ERANGE/FE_OVERFLOW in non-nearest rounding modes because it relies on host std::scalbn/std::exp.
EVIDENCE_ALREADY_SOLVED: Partial — merged PRs #23467 (exp/cosh overflow + errno + FE_OVERFLOW/FE_INEXACT for large args), #23410 (asin/atan FE_INEXACT), #23456 (ldexp), #10226 (lgammaf), #10007 (g1pf) fix many bits/flags differences, but the rounding-mode-dependent rows (differences appearing only when rounding down/toward zero) are explicitly left unfixed by the maintainer. Repo core/libs/prx/libc/src/Math.cpp:1148 still uses std::scalbn and _Exp uses std::exp, so the described symptom (returns DBL_MAX when rounding up vs module's ERANGE/FE_OVERFLOW/FE_INEXACT) is present.
DIFFICULTY: hard
WHY: The issue is a genuine, currently-unsolved numerical-fidelity gap for the libc libm. It is a survey that already documents several rows as "open in" linked PRs (exp2, sinh, pow, cosh, ldexpl, nextafter), but the central novel contribution — per-rounding-mode overflow/underflow flag and errno fidelity — has no open PR yet and is not fixed in main. It is hard because it requires emulating the module's exponent-field rounding behaviour across exp/exp2/cosh/sinh/pow and their f/l variants plus errno handling, verified against the native module in four rounding modes with DAZ/FTZ.
